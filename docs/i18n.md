# i18n

UI text lives in `lib/i18n/en.ts` and `lib/i18n/id.ts`: flat dotted keys (`area.thing`), `{name}` placeholders.

- `t(locale, key, params?)` in `lib/i18n/index.ts`.
- Server components and routes: `await getLocale()` / `await getT()` from `lib/i18n/server.ts`.
- Client components: `useT()` from `lib/i18n/client.tsx`; the root layout mounts `I18nProvider`.
- Host pages (dashboard, account, ops): `lang` cookie, then `Accept-Language`, then `en`. The cookie is set by `PUT /api/auth/locale` (stores `users.locale`) and by login / the 2FA step from `users.locale`, so a new device follows the saved choice.
- Audience pages (`/join/<code>`, `/e/<id>`, `/survey/<id>`, `/present/<id>`): the participant's own choice for that event (cookie `lang_<eventId>`, set by `AudienceLanguage`), then `events.audience_locale`, then the host order above. The presenter ignores the participant cookie. `proxy.ts` passes the path as `x-audience-path` so `getLocale()` (and so the root layout, `<html lang>` and the shell header) can look the event up; any new audience route must be added to its matcher and to `audienceTarget` in `lib/i18n/locale.ts`. `resolveLocaleFrom` is the single place that holds the order.
- `id.ts` is typed as `Record<MessageKey, string>`, so a missing or extra key fails typecheck; `tests/i18n.test.tsx` checks the same at runtime.
- `lib/copy.ts` keeps its old constants, now read through `t('en', ...)`.

**Rule: no inline UI strings in new code.** Add the key to both files first.

## Indonesian register

- Participant screens (join, participant view, Q&A, notes, open text, rating, ranking, quiz, survey form, shell chrome on audience pages) address the reader as **kamu** (`-mu` as a suffix). Host screens (dashboard, account, members, plan, billing, ops) use **Anda**. A participant key with "Anda" in it fails `tests/i18n-participant.test.ts`.
- Write Indonesian the way a short UI label would be written, not word for word from English: "Sisa 2 jawaban", not "2 jawaban tersisa". Polite, no forced slang, no exclamation marks.
- Keep **host** (not "penyelenggara"), **acara** for event, **Tanya jawab** for Q&A, **Dukung** for upvote, **poin** for points. Indonesian has no plural forms, so `.one` and `.other` hold the same wording.
- `tests/i18n-participant.test.ts` lists the key prefixes that count as participant copy. An `id` value equal to its `en` value fails there unless the key is in `SAME_IN_BOTH` (names such as the brand). A new participant key goes under one of those prefixes or the prefix is added to the list.
- Presenter and results screens (`presenter.*`, `presNotes.*`, `presAnalysis.*`, `presQuiz.*`, `presSurvey.*`, `presQa.*`, `presRanking.*`, `presOpenText.*`, `presRating.*`, `podium.*`, and `analysis.*` for the published analysis) are on the same test and read like participant copy: the big screen is read by the audience ("kamu", never "Anda"). Where a key is only for the host (`presAnalysis.none`), leave the pronoun out. `.one` with a literal "1" in English keeps the literal in Indonesian (no `{n}`).
- Host-side keys under `dash.*`, `eventMgr.*`, `pollMgr.*`, `moderation.*`, `moderatePage.*`, `openTextHost.*`, `notesAnalysis.*`, `analysisEditor.*`, `templates.*`, `survey.*`, `settings.*`, `retention.*`, `participantData.*`, `branding.*` are translated and covered by `tests/i18n-host.test.ts` (Anda, never kamu; no English copies). `members.*`, `plan.*`, `account.*`, `security.*`, `ops.*`, `auth.*`, `audit.*`, `role.*`, `workspace.*`, `verify.*`, `forgot.*`, `reset.*`, `invite.*`, `suspended.*` and `logout.*` are translated too (US-023); `api.*` and `email.*` are translated too (US-024, covered by `tests/i18n-api-email.test.ts`). Say **ruang kerja** for workspace and **acara** for event (never "event" in a sentence). The host's own badge is `members.you` ("Anda"), not `common.you`. Tier names (`plan.name.*`) stay Free, Pro, Team. Type names: Polling, Awan kata, Catatan bersama, Teks terbuka, Penilaian, Tanya jawab.

## API errors

Routes return `{ error }` with the text in the request locale: `serverT(request, key, params)` from `lib/i18n/server.ts` (keys are `api.*`). The status and response shape do not change. Lib code that fails returns `{ ok: false, error: <MessageKey>, params? }` and the route turns it into text with `apiMessage(request, result)`. Clients show the returned message as-is. The owner-only `/api/ai/test` diagnostic still returns English.

A client must never compare `body.error` with its own `t("api...")`: the server may answer in another language (audience pages follow the event, API routes follow the `lang` cookie / Accept-Language). Add a `reason` to the response and key on that (`alreadyAnswered`, `timeUp`, `alreadyRanked`, `alreadySubmitted`).

## Emails

`emailLocale(db, email, fallback)` (lib/i18n/email-locale.ts) picks the language: the recipient's `users.locale` when the address has an account that chose one, else `fallback`, which is the request's language (`requestLocale(request)`) for verification, reset and invitation mail and `DEFAULT_LOCALE` for the retention job. A new email adds `email.<name>.subject` / `.body` keys and goes through `emailLocale`.

## Dates and amounts

Format dates with `formatDay` (UTC calendar day, e.g. "20 Okt 2026") or `formatMoment` (viewer's zone, client-only) from `lib/format-date.ts`, passing `useLocale()` / `getLocale()`; amounts use `Intl.NumberFormat(locale, {style: "currency", currency})` (IDR gives "Rp 150.000"). Never `toLocaleString()` without a locale or `toISOString().slice(0, 10)` in a screen: a browser in another language breaks hydration. Emails keep the ISO day (`formatDeletionDay`).
