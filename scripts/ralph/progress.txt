## Codebase Patterns
- Dev server is `tsx server.ts` (custom Node server: Next.js + Socket.IO at /socket.io); PORT env overrides 3000.
- server.ts loads .env.local via dotenv; Next also loads it itself.
- Vitest tests live in tests/**/*.test.{ts,tsx}; config is vitest.config.mts (.mts avoids a CJS/ESM warning); `@` alias = repo root.
- DB: Drizzle + pg. `createDb(url)` in db/client.ts; migrations via `npm run db:migrate[:test]`; DB tests use `// @vitest-environment node` + tests/helpers/db.ts (`createTestDb`, `truncateAll`).
- Route handlers are plain `(request: Request)` functions; tests import and call them directly. App DB comes from `getDb()` in lib/db.ts (reads DATABASE_URL lazily) — DB tests set `process.env.DATABASE_URL = process.env.TEST_DATABASE_URL` in beforeAll before dynamically importing routes.
- Admin-only endpoints: `const auth = await requireAdmin(request); if (!auth.ok) return auth.response;` (lib/auth/require-admin.ts), then use `auth.user`.
- Rate limiting: `await rateLimit(key, limit, windowSeconds)` from lib/rate-limit.ts returns `{allowed, remaining, retryAfterSeconds}`; use `clientIp(request)` for IP keys; store is swappable via `setRateLimitStore`. Tests that hit limited routes should `await getRateLimitStore().reset()` in beforeEach.
